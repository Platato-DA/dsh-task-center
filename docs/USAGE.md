# 安装与使用 / Usage

## 版本与安装

支持范围为 DSH **0.2.1-rc.5**，插件 **0.1.0-beta.2**。首次使用 Desktop
应先启动一次完成初始化，再完全退出。安装前保留自己的 DSH 配置与任务数据备份。

推荐下载 GitHub Release 的 `.tgz`，在下载目录执行：

```sh
dsh plugin --profile desktop add ./dsh-external-dsh-task-center-0.1.0-beta.2.tgz
```

也可以安装带预构建产物的固定标签：

```sh
dsh plugin --profile desktop add 'github:pallwalt/dsh-task-center#v0.1.0-beta.2'
```

开发者可克隆后构建，再通过绝对路径安装本地目录：

```sh
pnpm install --frozen-lockfile
pnpm gate
dsh plugin --profile desktop add "$(pwd)"
```

路径安装通常会链接到源码目录。后续构建可能改变下一次加载的插件代码，删除源码目录也会使该安装失效。正式使用建议采用 Release 包。

使用 web profile 的开发者可以把 `desktop` 换成 `web`；首版的实际安装截图与既有宿主验收来自 macOS Desktop，其他环境请参阅 [兼容范围](COMPATIBILITY.md)。

## 升级与卸载

升级前完全退出 Desktop、备份数据，再用新版本 `.tgz` 重新执行 `add`。启动后可刷新界面以加载客户端新包。不要卸载原生 `@deepseek-ai/dsh-client-ui-schedule`；本插件依靠其原有侧栏入口。

```sh
dsh plugin --profile desktop list
dsh plugin --profile desktop remove @dsh-external/dsh-task-center
```

卸载后重新打开 Desktop，自动化任务页恢复为原生页面。插件任务、历史记录与产物留在磁盘上，不会被卸载命令主动清理。删除任务也不会删除产物与历史记录。

## 新建任务

- **模型**：可选 provider/model 与模型公布的思考强度。新建时选择默认模型会固化创建时的选择；运行配置只作用于任务会话。
- **工作目录**：宿主登记的工作区、自定义绝对路径或任务独立目录。绑定工作区消失会明确失败，需在编辑器里重新选择。
- **会话模式**：独立模式每次新建；持续模式复用该任务的专属会话。更换模型或目录可能需要新会话。
- **权限**：选择 DSH 的原生预设。完全权限须在表单中人工确认，对话工具不能直接把权限设为完全权限。旧任务可能显示“旧组合”，应在编辑中确认。
- **附件**：每行一个绝对路径，仅将路径写进提示词，不会复制或上传文件。
- **状态**：先暂停保存可避免未来自动触发；“立即运行”仍然可以手动执行暂停任务。

提示词应给出输入范围、产物文件名、格式以及完成条件。模板提供 AI 新闻 HTML 日报、工作文件夹周报和空白任务；新闻模板依赖宿主有可用的检索工具。

## 调度

| 规则 | 输入 |
| --- | --- |
| 单次 | 日期与时间 |
| 固定间隔 | 分钟数，以创建时间为锚点 |
| 每天 | `HH:mm` |
| 每周 | 星期与 `HH:mm` |
| Cron | 五字段 `分 时 日 月 周`，最小一分钟 |

时区保存为 IANA 名称，如 `Asia/Shanghai` 或 `America/New_York`。DST 春季缺失时刻跳过；秋季重复时刻取较早一次。Cron 支持 `@daily` 等常用别名，暂不支持秒字段、`L/W/#` 或月份名。

错过时可选择补跑最近一次或跳过。补跑不逐次重放所有历史计划。同一任务串行，全局并发默认 2。失败/超时可按次数重试，默认 1 次，退避为 60 秒乘尝试次数。重试可能重复外部副作用，请让任务自行保持幂等。

## 结果与数据

默认数据根为 `$DSH_HOME/storages/dsh-task-center/`，`DSH_HOME` 未设置时使用 `~/.dsh/`。

| 位置 | 内容 |
| --- | --- |
| `state.json` | 任务定义与运行记录，JSON 原子写入 |
| `workspaces/<taskId>/` | 默认的任务工作目录 |
| `tasks/<taskId>/` | 未指定工作目录任务的跨次数据 |
| `<工作目录>/.dsh-task-center/<taskId>/` | 指定工作目录任务的跨次数据 |
| `<工作目录>` | 实际产物 |

运行记录展示真实 `turn/end` 状态，但不会评价内容质量。产物按运行开始后的文件修改时间扫描，深度默认 3，最多 500 个文件，忽略点目录、符号链接及常见构建目录。其他程序同期改动的文件也可能被收录。

beta.2 起，运行详情保存并显示本次实际的超时设置和截止时间。期限在开始执行时固定，包含准备会话、模型和权限所花的时间；编辑任务不会追溯改变已经开始的运行。期限之后才到达的完成事件按超时处理，避免定时器晚回调时误记成功。持续会话在超时或取消后会改用新会话，隔离旧运行迟到的事件。旧历史没有这两个新字段时会显示“旧记录未保存”。

状态文件损坏时会保留 `.corrupt-*` 文件；记录部分不合法时先保留 `.invalid-*.bak` 备份，再加载可识别记录。旧格式迁移另写 `.pre-workspace-*.bak`。备份包含私人提示词与路径，请不要上传到 issue。

## 宿主配置与诊断

默认值：`maxConcurrentRuns: 2`、`runHistory: 300`、`defaultTimeoutMinutes: 20`、`graceSeconds: 90`、`diagnostics: false`。可在 DSH 的插件配置层覆盖该插件行的 `config`。修改前遵循宿主的配置说明并备份；无需修改全局模型。

管理界面使用同源 `POST /dsh-task-center/api`，只读状态可用 `GET .../api?op=state`；探针为 `GET /dsh-task-center/ping`。端口来自宿主，不应硬编码。

`debug`、`graph`、`tools`、`session.permission`、`tick`、`verify.chat` 仅在
`diagnostics: true` 时可用。`tools` 可以创建会话，`tick` 可以触发计划，
`verify.chat` 会真实调用模型、可能收费并创建任务。请在隔离测试环境中明确需要时才启用。

## 常见问题

- **看不到入口或有重复页注册错误**：确认宿主为 rc.5、原生侧栏插件仍启用、重启后刷新了界面。本插件用 `main/schedules` 的 `priority: -10`，保留原生注册。
- **页面 503**：缺少宿主信任检查能力时接口拒绝访问；不要绕过校验，确认宿主版本和服务加载情况。
- **任务失败**：打开运行详情，再进入执行会话查错误。模型被移除、工作区消失或权限服务不可用均会明确失败。
- **一直等待审批**：所选原生权限要求人工审批。无人应答最终会超时；请检查任务需要的操作与权限，勿默认改成完全权限。
- **HTML 预览部分内容不可用**：预览禁止脚本及外部资源，允许内联样式与部分内嵌资源，以保护宿主来源。
- **退出后没准点运行**：插件没有后台守护服务，DSH 退出或系统休眠期间不执行。

故障报告请包含插件/DSH/系统版本、任务规则、时区、会话模式及脱敏错误。安全问题见 [SECURITY.md](../SECURITY.md)。
